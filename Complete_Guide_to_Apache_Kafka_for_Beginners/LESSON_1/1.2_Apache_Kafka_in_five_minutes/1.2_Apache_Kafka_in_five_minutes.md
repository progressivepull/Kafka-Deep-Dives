# 1.2 Apache Kafka in five minutes

---

## The Data Integration Problem

Companies start with a simple need: move data from a **source system** (e.g. a database) to a **target system**.

Initially this is handled with custom ETL (Extract–Transform–Load) code.  
As the organization grows, the number of sources and targets multiplies.  
With 4 source systems and 6 target systems you already need **24 separate integrations**.

Each integration brings its own challenges:

- **Protocols** – TCP, HTTP/REST, FTP, JDBC, etc.
- **Data formats** – Binary, CSV, JSON, Avro, Protobuf…
- **Schema evolution** – what happens when the shape of the data changes?
- **Load on sources** – every new consumer adds pressure on the original systems

The result is a tightly coupled, hard-to-maintain web of point-to-point connections.

---

## How Kafka Solves It

Apache Kafka sits in the middle as a **central, durable data stream**.

- **Source systems** *produce* (write) data into Kafka.
- **Target systems** *consume* (read) data from Kafka.

Sources and targets are now decoupled. Adding a new consumer or producer no longer requires new point-to-point integrations.

### Typical data flows

| Sources (Producers)          | Targets (Consumers)          |
|-----------------------------|------------------------------|
| Website events              | Databases                    |
| Pricing data                | Analytics systems            |
| Financial transactions      | Email / notification systems |
| User interactions           | Audit / compliance systems   |

---

## Why Kafka Is Powerful

| Characteristic              | Benefit                                      |
|----------------------------|----------------------------------------------|
| Distributed & fault-tolerant | Maintenance and upgrades without downtime   |
| Horizontal scalability     | Add brokers; scale to hundreds of nodes      |
| High throughput            | Millions of messages per second              |
| Low latency                | Often < 10 ms → true real-time capability    |
| Wide adoption              | 2,000+ public companies; ~80 % of Fortune 100 |

Kafka was created at **LinkedIn** and is now maintained by major organizations including Confluent, IBM, Cloudera, and LinkedIn itself.

---

## Common Use Cases

- Messaging / pub-sub
- Activity & user tracking
- Metrics collection
- Application log aggregation
- Stream processing (Kafka Streams, Spark, Flink, Storm…)
- Microservices decoupling
- Integration with the wider big-data ecosystem

### Real-world examples

- **Netflix** – real-time recommendations while you watch
- **Uber** – real-time demand forecasting and dynamic pricing
- **LinkedIn** – spam prevention and connection recommendations

In all these cases Kafka acts as the high-throughput, low-latency **transport layer** that moves data reliably across the company.

---

## Key Takeaway

Apache Kafka turns a fragile mesh of point-to-point integrations into a scalable, resilient, real-time data backbone. Sources write once; any number of consumers can read the same stream independently and at their own pace.
