# 4.2 Kafka topics CLI

This lecture demonstrates how to manage Apache Kafka topics using the `kafka-topics` command-line utility, both against a local Kafka broker and the Conduktor playground cluster. The instructor uses the Conduktor UI to visually verify CLI actions.

## Learning objectives

- Create Kafka topics.
- List and describe topics.
- Specify partition counts and replication factors.
- Understand leaders, replicas, and in-sync replicas (ISR).
- Delete topics.
- Connect to local and secured clusters.

## 1. CLI command structure

For a local broker, the basic structure is:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

- `kafka-topics.sh`: Kafka topic management utility (command name varies by installation).
- `--bootstrap-server`: Kafka broker address used to establish a connection.
- `--list`, `--create`, `--describe`, `--alter`, or `--delete`: action to perform.
- `--topic`: topic name for actions that target a particular topic.

Running a command without an action may display CLI usage documentation.

### Connecting to the Conduktor playground

The lecture creates a `playground.config` file containing three connection-property lines, including credentials, then passes it to the CLI:

```bash
kafka-topics.sh \
  --command-config playground.config \
  --bootstrap-server <PLAYGROUND_BOOTSTRAP_SERVER> \
  --list
```

The transcript does not provide the actual three property lines or server address. Use the course's downloadable code for those values. Keep credentials private and restrict access to the config file.

## 2. Create a topic

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic first_topic
```

To specify partitions explicitly:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic second_topic --partitions 5 --replication-factor 1
```

A topic can contain multiple partitions, which distribute its records across partition logs.

## 3. Replication factor and brokers

Replication factor specifies how many broker copies of each partition are maintained.

- A topic's replication factor cannot exceed the number of available brokers.
- The lecture's local Kafka setup has one broker, so it supports a replication factor of **1**.
- The Conduktor playground has multiple brokers (39 in the instructor's example, though this can vary).
- The instructor notes that the playground enforces a replication factor of **3**, even when another value is requested.

A replication factor of 2 fails on the single-broker local setup.

## 4. List topics

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

This displays the topic names available to the connected Kafka cluster.

## 5. Describe a topic

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --describe --topic first_topic
```

The output includes the topic name, partition count, replication factor, and per-partition information:

| Field | Meaning |
|---|---|
| `Partition` | Partition identifier within the topic |
| `Leader` | Broker ID currently leading the partition |
| `Replicas` | Broker IDs holding copies of that partition |
| `Isr` | In-sync replica broker IDs |

For example, `Partition: 0`, `Leader: 31`, `Replicas: 31,15,5`, `Isr: 31,15,5` indicates that partition 0 has three replicas, all in sync, with broker 31 as leader.

On the lecture's single-broker local cluster, the leader, replicas, and ISR can all show broker ID `0`. **Partition ID 0 and broker ID 0 are different identifiers.**

## 6. Increase partitions

The lecture identifies increasing partition count as a topic-management task, although the transcript does not demonstrate the command. A typical example is:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --alter --topic first_topic --partitions 5
```

**Additional context:** Increasing partitions is supported, but reducing partition count is not supported by this command. Changing partition count can affect key-to-partition assignment.

## 7. Delete a topic

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --delete --topic second_topic
```

The instructor also demonstrates deleting topics through the Conduktor UI.

**Lecture warning:** The instructor advises users running Windows without WSL2 **not to delete topics**, because that environment can crash in the course setup. Deleting a topic also removes its data; verify the target before running the command.

## 8. Local Kafka vs. Conduktor playground

| Feature | Local Kafka | Conduktor playground |
|---|---|---|
| Connection | `localhost:9092` in the lecture | Hosted bootstrap server |
| Authentication | No extra config in the lecture | `--command-config playground.config` |
| Brokers | One in the lecture | Multiple |
| Replication factor | Maximum 1 with one broker | Enforced as 3 in the instructor's playground |
| Visual feedback | Depends on local UI availability | Conduktor console UI |

The instructor recommends the playground because it helps learners see topic and partition changes immediately and practice connecting to a secured Kafka cluster.

## Key takeaway

The `kafka-topics` CLI is a core tool for managing Kafka topics. Learn to create, list, describe, alter, and delete topics, and to interpret partition and replica metadata. The Conduktor UI can make these CLI operations easier to understand.

## Key concepts
1. Create topics: Create Kafka topics using the CLI.
2. List topics: Display all available Kafka topics.
3. Describe topics: View partitions, leaders, replicas, and in-sync replicas (ISR).
4. Partitions: Specify or increase the number of partitions.
5. Replication factor: Understand how Kafka distributes partition replicas across brokers.
6. Delete topics: Remove topics using the CLI or Conduktor UI.
7. Secure connections: Use --command-config to connect to secured Kafka clusters.

## Important Kafka CLI commands

| Operation	           | Command option         |
|----------------------|------------------------|
| Create topic	       | --create               |
| List topics	       | --list                 |
| Describe topic	   | --describe             |
| Increase partitions  | --alter                |
| Delete topic	       | --delete               |
| Specify partitions   | --partitions           |
| Specify replication  | --replication-factor   |

Example: Create a Kafka topic
```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create \
  --topic first_topic \
  --partitions 3 \
  --replication-factor 1
```

Example: Describe a Kafka topic
```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --topic first_topic
```

Key takeaway: The Kafka Topics CLI allows you to manage topics directly from the terminal and understand how partitions and replicas are distributed across Kafka brokers.
