# 4.3 Kafka console producer CLI

This lecture demonstrates how to use the **Kafka console producer** to send messages to Kafka topics. It covers producing messages without keys, configuring acknowledgments, handling nonexistent topics, and producing messages with keys. Examples work with a local Kafka broker or a secured Conduktor playground, with different connection options.

## 1. Prepare a topic

Create a topic named `first_topic` with one partition for the demonstration:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic first_topic --partitions 1 --replication-factor 1
```

The lecture uses one partition initially, so every message lands in that partition regardless of its key.

## 2. Produce messages without keys

Start the interactive producer:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic first_topic
```

Enter one message per line, pressing **Enter** to send each message:

```text
hello world
my name is Tom
I love Kafka
```

The prompt (`>`) indicates the producer is waiting for input. Press **Ctrl+C** to exit. By default, these console-producer messages have **null keys**. You can inspect the records in the Conduktor UI or consume them with a Kafka consumer in the next lesson.

### Secured playground connection

For a secured Kafka cluster, the instructor uses a local connection configuration file (such as `playground.config`) and supplies it to the producer:

```bash
kafka-console-producer.sh \
  --producer.config playground.config \
  --bootstrap-server YOUR_BOOTSTRAP_SERVER \
  --topic first_topic
```

Use the actual bootstrap address and the credentials/settings supplied by the playground. Do not publish the config file if it contains passwords.

## 3. Configure producer acknowledgments

Use `--producer-property` to customize producer behavior:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic first_topic \
  --producer-property acks=all
```

**`acks=all`** requests acknowledgment from all **in-sync replicas** required by the broker configuration, not literally every broker in the cluster. This strengthens delivery durability compared with weaker acknowledgment settings.

## 4. Producing to a nonexistent topic

If you produce to `new_topic` before creating it, behavior depends on the cluster configuration:

- **Conduktor playground in the lecture:** Automatic topic creation is disabled, so the producer eventually reports an error because the topic does not exist.
- **Local Kafka setup in the lecture:** Automatic topic creation is enabled, so Kafka may create the topic after a short delay; transient leader-related warnings may appear while it initializes.

Check whether the topic exists:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

Kafka's broker configuration can control the default partition count for automatically created topics (for example, `num.partitions=3` in `config/server.properties`). **Best practice:** Create topics explicitly rather than depending on automatic creation.

## 5. Produce messages with keys

To enter a key and a value on each line, enable key parsing and choose a separator:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic first_topic \
  --property parse.key=true \
  --property key.separator=:
```

Example input:

```text
example_key:example_value
name:Tom
name:Kafka learner
```

The text **before** `:` is the key; the text **after** it is the value. Omitting the separator while key parsing is enabled results in an error.

Keys help determine message partition placement. With a stable key and the same partitioning configuration, records with that key normally go to the same partition. Because `first_topic` has only **one partition** in this demonstration, the lecture cannot yet illustrate key-based distribution across multiple partitions.

## 6. Quick command reference

| Task | Option or command |
|---|---|
| Start interactive producer | `kafka-console-producer.sh` |
| Choose Kafka cluster | `--bootstrap-server localhost:9092` |
| Choose destination topic | `--topic first_topic` |
| Connect to secured cluster | `--producer.config playground.config` |
| Require in-sync replica acknowledgments | `--producer-property acks=all` |
| Parse input keys | `--property parse.key=true` |
| Use colon between key and value | `--property key.separator=:` |
| Exit interactive producer | `Ctrl+C` |

> **OS note:** The commands above use the `.sh` scripts for Linux, macOS binary installs, and WSL2. Adapt the executable name to your Kafka installation.

## Key takeaways

1. The Kafka console producer sends one message each time you press Enter.
2. Messages are sent with null keys unless you enable key parsing.
3. Producer settings such as `acks=all` affect acknowledgment behavior.
4. Automatic topic creation depends on cluster configuration; explicit creation is recommended.
5. Keyed messages can preserve partition affinity for the same key, which is more meaningful with multiple partitions.
6. Conduktor provides visual feedback for inspecting produced records.

## Key concepts
1. Kafka Console Producer: Sends messages to Kafka topics using the terminal.
2. Producing without keys: Messages have null keys and can be distributed across partitions.
3. Producing with keys: Messages with the same key normally go to the same partition.
4. Producer acknowledgments: Use acks=all to request acknowledgment from all required in-sync replicas.
5. Automatic topic creation: Kafka may automatically create nonexistent topics depending on broker configuration.
6. Secure connections: Use --producer.config to connect to secured Kafka clusters.
7. Conduktor UI: View produced messages, keys, values, and partitions.
