# 4.6 Kafka consumer groups CLI

This lecture demonstrates how to inspect and manage Kafka consumer groups using the `kafka-consumer-groups` command-line tool and the Conduktor UI. The practical focus is on listing groups, describing their offsets and lag, and observing partition assignments as consumers join a group. The instructor introduces deletion as a management operation, but does not demonstrate a deletion command in the supplied transcript.

## Learning objectives

- List existing consumer groups.
- Describe a consumer group's topic partitions, committed offsets, log end offsets, and lag.
- Observe lag increasing when new messages arrive and decreasing when a consumer catches up.
- Identify which consumer owns each partition.
- Understand the temporary groups created by console consumers without a specified group ID.

## 1. List consumer groups

```bash
kafka-consumer-groups.sh --bootstrap-server localhost:9092 --list
```

The lecture shows two previously created groups: `my-first-application` and `my-second-application`. The Conduktor UI can also display them.

## 2. Describe a group

```bash
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --group my-second-application
```

Typical output includes:

| Field | Meaning |
|---|---|
| GROUP | Consumer group ID |
| TOPIC | Topic being consumed |
| PARTITION | Partition number |
| CURRENT-OFFSET | Last committed position (next record offset to process) |
| LOG-END-OFFSET | End offset of the partition |
| LAG | Difference between log end and committed offsets |
| CONSUMER-ID | Consumer currently assigned to the partition, if active |
| HOST | Host associated with the consumer |

**Consumer lag = LOG-END-OFFSET − CURRENT-OFFSET** (when both offsets are available).

For example, a current offset of 14 and log end offset of 14 means lag is 0.

## 3. Produce messages and observe lag

Start a producer in a separate terminal:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic third_topic
```

Enter several messages, such as `A`, `B`, `C`, and `D`, and stop the producer with `Ctrl+C`.

Describe `my-second-application` again. The lecture shows three partition lag values of **2, 1, and 2**, totaling **5 messages**. These messages arrived after the group had stopped consuming.

## 4. Resume the group and catch up

```bash
kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic third_topic \
  --group my-second-application
```

The consumer reads the messages it missed. After offsets are committed and the group catches up, describing the group shows lag returning to **0**.

## 5. Add another consumer to the same group

Run the same consumer command in a second terminal. Kafka rebalances partition assignments between the two consumers. In the lecture's example, one consumer owns partitions 0 and 1, while the other owns partition 2.

The `--describe` output now includes different consumer IDs for the assigned partitions. The Conduktor UI shows the same assignments.

**Important:** Within a consumer group, each partition is assigned to one consumer at a time. Different groups can independently read the same topic.

## 6. Console consumers without an explicit group

```bash
kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic third_topic \
  --from-beginning
```

The lecture demonstrates that the console consumer can create an automatically named, temporary group. Such group IDs may appear in the group list for a while and later disappear. For applications that need consistent offset tracking, explicitly choose a stable group ID.

## Key takeaway

The Kafka Consumer Groups CLI makes it possible to monitor **who is consuming each partition**, **how far a group has progressed**, and **whether messages are waiting to be processed**. Stable group IDs preserve an application's committed offsets, while adding consumers can redistribute partition ownership.

*Note: These examples assume Kafka binaries are installed and on your PATH. For secure clusters, additional connection configuration is required.*


## Key concepts
1. Consumer groups: Allow multiple consumers to read Kafka topics and distribute partitions among group members.
2. List consumer groups: Use --list to display existing consumer groups.
3. Describe consumer groups: Use --describe to inspect partition assignments, offsets, and lag.
4. Current offset: The last committed consumer position, representing the next offset to read.
5. Log end offset: The next offset to be written to a partition.
6. Consumer lag: The difference between the log end offset and the committed offset.
7. Consumer rebalancing: Kafka redistributes partitions when consumers join or leave a group.
8. Temporary consumer groups: Console consumers without an explicit group ID can create automatically named groups.

```bash
kafka-consumer-groups.sh \
```


**Example 3: Start a consumer in an existing group**
```bash
kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic third_topic \
  --group my-second-application
```

Understanding consumer lag
$$
\text{Consumer Lag} = \text{Log End Offset} - \text{Current Offset}
$$

For example, if the log end offset is 27 and the committed offset is 25, the consumer lag is 2 messages.

Key takeaway: The Kafka Consumer Groups CLI helps you monitor consumer progress, identify lag, and inspect how Kafka assigns partitions to consumers.
