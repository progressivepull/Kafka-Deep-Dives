# 4.1 CLI introduction

This lecture introduces the **Apache Kafka Command-Line Interface (CLI)**, which will be used for hands-on exercises throughout the course. The CLI tools are bundled with the Kafka binaries. Once the Kafka `bin` directory is added to your system's `PATH`, you can run commands from any directory.

## Key Concepts

1. **Kafka CLI tools are included with Kafka binaries.** No separate CLI download is needed when the Kafka binaries are already installed.
2. **The `PATH` variable makes commands accessible everywhere.** Otherwise, invoke a CLI tool using its full file path.
3. **Command names vary by installation method and operating system.** Use the form appropriate to your environment.
4. **Use `--bootstrap-server` to connect to Kafka.** The lecture recommends this option instead of the older `--zookeeper` option.
5. **A `command not found` error often indicates a PATH or command-name issue.** Try the full executable path if needed.

## Kafka CLI Command Names

| Environment / installation | Example command |
|---|---|
| macOS or Linux with extracted Kafka binaries | `kafka-topics.sh` |
| Windows WSL2 with Linux Kafka binaries | `kafka-topics.sh` |
| Windows without WSL2, using Windows Kafka scripts | `kafka-topics.bat` |
| Package-manager installation such as Homebrew or APT (as described in the lecture) | `kafka-topics` |

**Note:** The instructor demonstrates the command form used by their own installation. Adapt it to your setup.

## Using the Bootstrap Server

The course uses a Kafka broker accessible at `localhost:9092`.

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

This example lists topics on the broker. Replace `kafka-topics.sh` with the appropriate command name for your installation.

The lecture emphasizes using `--bootstrap-server` instead of the older ZooKeeper-based command option:

```text
--bootstrap-server localhost:9092
```

## Troubleshooting: Command Not Found

If entering `kafka-topics.sh` does not work:

1. Check that Kafka binaries were installed.
2. Confirm which command form your installation provides (`.sh`, `.bat`, or no suffix).
3. Check that the Kafka `bin` directory was added to `PATH`.
4. If the PATH configuration still fails, run the command with its **full path**.

Example on Linux, macOS, or WSL2 (adjust the directory name to match your installation):

```bash
~/kafka_2.13-4.0.0/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

## Key Takeaway

**The Kafka CLI is the main hands-on tool for the next course section.** Use the command name appropriate to your operating system, connect to the broker using `--bootstrap-server`, and fall back to the executable's full path if your `PATH` is not configured correctly.

## Key concepts
1. Kafka CLI: Command-line tools included with Apache Kafka binaries.
2. PATH configuration: Allows Kafka commands to run from any directory.
3. Operating system differences: Commands may use .sh, .bat, or no extension.
4. Bootstrap server: Connect to Kafka using --bootstrap-server localhost:9092.
5. ZooKeeper: The course recommends using bootstrap-server commands instead of older ZooKeeper-based commands.
6. Troubleshooting: Use the full path to Kafka binaries if commands are not recognized.

## Kafka CLI commands by operating system
Operating system	Command
Linux	kafka-topics.sh
macOS (manual installation)	kafka-topics.sh
Windows WSL2	kafka-topics.sh

Example: List Kafka topics
```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --list
```

Example: Run Kafka CLI using the full path
```bash
~/kafka_2.13-4.0.0/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --list
```

Adjust the directory to match your installed Kafka version.

Key takeaway: Kafka CLI commands allow you to manage and interact with Kafka brokers directly from the terminal. Correct PATH configuration and the --bootstrap-server option are essential for the course exercises.
