# 5.1 Conduktor- Demo

This lecture introduces the **Conduktor UI** as a graphical interface for working with Apache Kafka. It demonstrates everyday topic and message operations, then surveys more advanced capabilities for managing Kafka in an organization.

## 1. Cluster overview and connections

- The **Home** screen provides information about the selected Kafka cluster, including recently viewed resources.
- The cluster selector lets users switch between and manage multiple Kafka clusters.
- Adding a cluster involves its display name, technical identifier, bootstrap servers, and authentication settings when required.
- Connection guides are available for different Kafka environments.

## 2. Browse topics and inspect records

- The **Topics** view lists topics in the selected cluster.
- Opening a topic displays records and their **keys, values, and timestamps**.
- Selecting an individual record reveals additional details, including **headers and metadata**.
- The UI can **reprocess** a record by sending it again to the same topic or to another topic.

## 3. Produce records from the UI

The **Produce** window lets users send Kafka records without writing CLI commands.

1. Choose the topic.
2. Enter or generate a record **key** and **value**.
3. Add headers if needed.
4. Produce a single record, or configure repeated production.

**Lecture example:** Generate random string keys and values, then configure automatic production at an interval of **one record per second**. This is useful for quickly testing a topic.

## 4. Create and organize topics

When creating a topic, the UI can specify:

- Topic name
- Number of partitions
- Replication factor
- Labels, such as `team=dev`
- Additional topic configuration settings

Labels help users filter and organize topics by team or purpose. The lecture demonstrates creating a demo topic and applying a development-team label.

## 5. Consumer group management

Conduktor provides a graphical view for consumer groups, including:

- Inspecting consumer groups
- Viewing consumer lag
- Resetting consumer offsets

These features complement the Kafka consumer groups CLI demonstrated in earlier lessons.

## 6. Additional capabilities shown

| Feature | Purpose described in the lecture |
|---|---|
| Schema Registry | Work with Kafka schemas when a registry is configured. |
| Kafka Connect | Connect to Kafka Connect when configured for the cluster. |
| Kafka Gateway | Support advanced policies, field-level encryption, auditing, and schema-related rules. |
| Brokers | Inspect brokers, their versions, and controller information. |

| Service accounts | Create accounts for applications. |
| ksqlDB | Manage ksqlDB through the UI. |

**Note:** The instructor states that some integrations, such as Schema Registry and Kafka Connect, are **not configured in the demonstrated environment**. Advanced features may require additional configuration or product capabilities.

## 7. Suggested practice exercise

1. Open Conduktor and select your Kafka cluster.
2. Browse an existing topic and inspect a record's key, value, timestamp, headers, and metadata.
3. Open the Produce view and send a test record.
4. Try generating records automatically at a one-second interval, then stop the producer.
5. Create a demo topic with an appropriate partition count and replication factor for your cluster.
6. Add a label such as `team=dev` and locate the topic using the UI.
7. Open Consumer Groups and inspect lag or offset-management options.

## Key takeaways

- **Conduktor makes Kafka operations visual:** users can browse topics, inspect records, produce messages, and manage consumer groups.
- **Topic labels** help organize Kafka resources across teams.
- **Automatic record generation** provides a quick way to test Kafka topics.
- **Advanced management features** extend beyond basic Kafka development into governance and organizational operations.
- The UI shown in later course lectures may look different, but the instructor emphasizes that the core **Topics** and **Consumer Groups** functionality remains relevant.

##Key concepts
1. Cluster management: Connect to and manage multiple Kafka clusters using bootstrap servers and authentication settings.
2. Topic management: Create topics, configure partitions and replication factors, and organize topics using labels.
3. Message inspection: View Kafka records, including keys, values, timestamps, headers, and metadata.
4. Message production: Produce records manually or automatically at configured intervals.
5. Consumer groups: Monitor consumer lag and reset consumer offsets.
6. Schema Registry: Manage Kafka schemas when configured.
7. Kafka Connect: Integrate Kafka with external data systems.
8. Kafka Gateway: Support advanced policies, encryption, and auditing.
9. Monitoring: Inspect Kafka brokers and configure alerting.
10. Enterprise management: Explore service accounts, chargeback, self-service, and data quality rules.

**Example: Automatically produce Kafka messages**
The instructor demonstrates using Conduktor to generate Kafka records automatically.
1. Open the Produce window.
2. Select a Kafka topic.
3. Configure a random string key.
4. Configure a random string value.
5. Enable automatic production.
6. Set the interval to 1 second.
7. Start producing messages.
8. Open the topic to inspect the generated records.
Key takeaway: Conduktor provides a graphical interface for managing Kafka topics, producing and inspecting records, monitoring consumer groups, and performing advanced Kafka administration without relying entirely on CLI commands.
