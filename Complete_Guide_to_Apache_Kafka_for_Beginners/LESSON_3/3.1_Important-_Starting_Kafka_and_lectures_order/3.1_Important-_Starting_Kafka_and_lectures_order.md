# 3.1 Important- Starting Kafka and lectures order

## Key Points

- Starting Kafka can be complicated, so the course provides different installation paths for macOS, Linux, and Windows.
- **Recommended:** Use Docker to start a single Kafka broker and Conduktor UI with one command provided in the following lecture.
- The Conduktor UI makes it easier to inspect and manage Kafka topics and clusters.
- The local Kafka broker is accessible at **`127.0.0.1:9092`** in the demonstrated setup.
- Install the **Kafka CLI binaries** separately even when using Docker, so you can interact with Kafka from the command line.
- A single broker is suitable for development and learning, but is not a production-ready multi-broker cluster.
- Kafka 4.0 and later use **KRaft (without ZooKeeper)**; older Kafka + ZooKeeper lessons are included for legacy setups.

## Recommended Lecture Order: Docker (Windows, macOS, Linux)

1. Install and launch Docker.
2. Follow the lecture to start **Kafka and Conduktor** together using the provided command.
3. Install the Kafka CLI tools using the Kafka binaries for your operating system.
4. Use the CLI and Conduktor UI to practice with your local Kafka broker.

**Why choose Docker?** It provides a consistent setup across operating systems and includes the UI used throughout the course.

## Alternative Lecture Order: Without Docker

| Operating system | Installation order | Notes |
| --- | --- | --- |
| **macOS** | Install Kafka CLI binaries (or use Homebrew), then start Kafka with the binaries. | Use the ZooKeeper-free KRaft setup. |
| **Linux** | Install Kafka CLI binaries, then start Kafka with the binaries. | Use the ZooKeeper-free KRaft setup. |
| **Windows 10 (version 2004+) / Windows 11** | Install **WSL2**, install Kafka CLI binaries inside the Linux environment, then start Kafka. | WSL2 is recommended over running Kafka directly on Windows. |
| **Older Windows** | Prefer the Docker-based method where supported. | Native Windows Kafka setup is not recommended in the lecture. |

**Important:** The non-Docker alternatives in this lecture do **not** include the Conduktor UI by default.

## Docker vs. Manual Installation

| Feature | Docker method | Manual binaries method |
| --- | --- | --- |
| Kafka broker | Yes | Yes |
| Conduktor UI in course setup | Yes | No |
| Kafka CLI tools | Install separately | Install as part of manual setup |
| Cross-platform convenience | High | OS-specific steps |
| Best for | Beginners and course exercises | Learning manual installation and administration |

## Legacy Kafka Setup

The course also includes optional lectures for older Kafka deployments using **ZooKeeper** on macOS and Linux. These are intended for legacy learning; modern Kafka 4.0+ uses KRaft instead.

## Key Takeaway

**Use Docker to start Kafka and Conduktor, then install the Kafka CLI tools for your operating system.** This is the instructor's preferred setup because it combines an easy local Kafka environment with the UI used during the course.

> **Note:** This summary describes the instructor's setup guidance. The exact Docker command and installation commands are provided in subsequent lectures, not in this transcript.

### Key concepts
1. Docker installation: Simplifies Kafka setup across Windows, macOS, and Linux.
2. Conduktor UI: Provides a graphical interface for managing Kafka topics and clusters.
3. Kafka CLI: Install Kafka binaries separately to interact with Kafka through terminal commands.
4. Kafka broker: The course uses one broker at 127.0.0.1:9092 for local development.
5. KRaft: Kafka 4.0+ operates without ZooKeeper.
6. Windows: WSL2 is recommended for installations without Docker.
