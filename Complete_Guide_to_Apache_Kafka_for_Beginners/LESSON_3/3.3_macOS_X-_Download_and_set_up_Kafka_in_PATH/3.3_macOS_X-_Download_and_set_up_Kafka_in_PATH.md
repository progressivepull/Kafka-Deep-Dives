# 3.3 macOS X- Download and set up Kafka in PATH

## Overview

This lesson explains how to install the Kafka command-line tools on macOS and add them to the shell `PATH`. **You need the Kafka binaries even when Kafka itself is already running through Docker and Conduktor**, because the CLI tools let you interact with the Kafka cluster from Terminal.

## Learning objectives

- Install Java JDK 21.
- Download and extract Apache Kafka binaries (Kafka 4.0 or newer in the lecture).
- Place Kafka in a convenient directory, such as your home folder.
- Add Kafka's `bin` directory to your `PATH` using `~/.zshrc`.
- Verify Kafka commands work from any directory.

## Step 1: Install Java JDK 21

The instructor uses **Amazon Corretto 21**, a production-ready OpenJDK distribution.

1. Visit the [Amazon Corretto downloads page](https://aws.amazon.com/corretto/).
2. Select the macOS package matching your processor:
   - **Apple Silicon (M-series):** `aarch64` / ARM64.
   - **Intel Mac:** `x64` / x86_64.
3. Install the package.
4. Open Terminal and verify Java:

```bash
java --version
```

The output should indicate Java 21 if you installed Corretto 21.

> If macOS requests Rosetta unexpectedly, double-check that you downloaded the package for your Mac's processor architecture.

## Step 2: Download Apache Kafka

1. Open the [official Apache Kafka downloads page](https://kafka.apache.org/downloads).
2. Download the Kafka **binary** distribution (the instructor demonstrates Kafka 4.0).
3. Extract the downloaded archive.
4. Move the extracted Kafka directory into your home directory (`~`), or another convenient location.

Check where you are and list directories:

```bash
cd ~
pwd
ls
```

For example, your Kafka directory might be `~/kafka_2.13-4.0.0`. The exact directory name depends on the version you downloaded.

## Step 3: Understand the PATH variable

The Kafka `bin` directory contains executable shell scripts such as `kafka-topics.sh`.

Without adding the directory to `PATH`, you must run the command using its full or relative location, for example:

```bash
~/kafka_2.13-4.0.0/bin/kafka-topics.sh
```

After adding the `bin` directory to `PATH`, you can run the command directly:

```bash
kafka-topics.sh
```

## Step 4: Add Kafka to PATH using zsh

macOS commonly uses the `zsh` shell. Open the shell configuration file:

```bash
nano ~/.zshrc
```

Add this line, **replacing the directory name with the one you actually extracted**:

```bash
export PATH="$PATH:$HOME/kafka_2.13-4.0.0/bin"
```

In nano, press **Ctrl+O**, then **Enter** to save, and **Ctrl+X** to exit. (Alternatively, follow nano's prompts if exiting with unsaved changes.)

Check the saved file:

```bash
cat ~/.zshrc
```

Apply the change immediately, or close and reopen Terminal:

```bash
source ~/.zshrc
```

> The lecture illustrates appending the Kafka `bin` path to `PATH`. Using `export` makes the updated variable available to commands launched from the shell.

## Step 5: Verify Kafka CLI access

Check whether the shell can locate the Kafka command:

```bash
command -v kafka-topics.sh
```

Then display its help:

```bash
kafka-topics.sh --help
```

If you get command output rather than `command not found`, the `PATH` is configured correctly. You can also type `kafka-` and press **Tab** to explore available Kafka commands (shell completion behavior can vary).

## Docker and Conduktor vs. Kafka CLI

| Component | Purpose |
|---|---|
| Docker and Conduktor | Start a local Kafka broker and provide a graphical interface. |
| Kafka binaries | Provide command-line utilities for managing and interacting with Kafka. |
| Java JDK | Provides the Java runtime needed for Kafka tools. |
| `PATH` configuration | Allows Kafka CLI commands to run without specifying their full file paths. |

## Troubleshooting

- **`java: command not found`**: Verify JDK installation and shell configuration.
- **Rosetta prompt on an M-series Mac**: Check whether you selected the ARM64 (`aarch64`) JDK package.
- **`kafka-topics.sh: command not found`**: Confirm that the Kafka `bin` directory exists and matches the path in `~/.zshrc`; then run `source ~/.zshrc`.
- **Kafka CLI installed but cluster unavailable**: Installing CLI tools does not start a Kafka broker. Start the broker separately using Docker/Conduktor or another Kafka startup method.

## Key takeaway

**Install Java, download Kafka binaries, and add Kafka's `bin` directory to your `PATH`** so Kafka commands are available anywhere in Terminal. If your Kafka broker is already running in Docker with Conduktor, you can use these tools to connect to that broker; otherwise, follow the next lecture to learn how to start Kafka without Docker.

## Key concepts
1. Install Java JDK 21: Use Amazon Corretto, selecting the correct version for Intel or Apple Silicon.
2. Download Apache Kafka: Obtain Kafka binaries from the official Apache Kafka website.
3. Extract Kafka: Place the extracted Kafka directory in your macOS home directory.
4. Configure PATH: Add Kafka's bin directory to ~/.zshrc.
5. Verify installation: Run Kafka CLI commands directly from Terminal.
6. Docker integration: Kafka CLI tools can connect to the Kafka broker running through Docker and Conduktor.

## Example PATH configuration

Add the following to ~/.zshrc, adjusting the Kafka directory name to match your installation:

```bash
export PATH="$PATH:$HOME/kafka_2.13-4.0.0/bin"
```


Then execute:

```bash
source ~/.zshrc
kafka-topics.sh --help
```


Key takeaway: Installing Kafka binaries and configuring PATH allows you to execute Kafka commands from anywhere in macOS Terminal, even when your Kafka broker is running separately through Docker and Conduktor.
