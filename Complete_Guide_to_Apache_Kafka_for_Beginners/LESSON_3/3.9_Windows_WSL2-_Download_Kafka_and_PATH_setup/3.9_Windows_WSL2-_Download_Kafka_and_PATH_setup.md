# 3.9 Windows WSL2- Download Kafka and PATH setup

This lecture explains how to install Java JDK 21 and Apache Kafka CLI tools inside Ubuntu running under Windows Subsystem for Linux 2 (WSL2). It also demonstrates how to add Kafka's `bin` directory to the Linux `PATH` so Kafka commands can be run from any directory.

> **Important:** Installing the Kafka binaries is useful even if your Kafka broker is already running in Docker with Conduktor. The binaries provide command-line tools to interact with the broker.

## Prerequisites

- Windows with WSL2 and Ubuntu installed.
- Access to the Ubuntu terminal and an internet connection.
- Permission to install packages in Ubuntu.

## Step 1: Install Java JDK 21

1. Open Ubuntu in WSL2.
2. Visit the [Amazon Corretto 21 installation instructions](https://docs.aws.amazon.com/corretto/latest/corretto-21-ug/linux-info.html).
3. Select the **Debian-based Linux** instructions, because Ubuntu is Debian-based.
4. Follow the official commands to configure the repository and install Amazon Corretto 21.
5. Verify the installation:

```bash
java --version
```

The output should identify Java 21 and Amazon Corretto. If a different Java version is selected, inspect the configured alternatives:

```bash
sudo update-alternatives --config java
sudo update-alternatives --config javac
```

## Step 2: Download Kafka Binaries

1. Open the [official Apache Kafka downloads page](https://kafka.apache.org/downloads).
2. Select a Kafka release (the instructor demonstrates Kafka 4.0.0 or later).
3. Copy the **binary** archive download link, not the source archive link.
4. In Ubuntu, use `wget` with the copied URL:

```bash
cd ~
wget 'PASTE_KAFKA_BINARY_DOWNLOAD_URL_HERE'
```

Replace the placeholder with the actual URL from the downloads page.

## Step 3: Extract Kafka

For a `.tgz` archive, run:

```bash
tar -xvzf kafka_2.13-4.0.0.tgz
ls
```

The archive name above is an example. Use the filename you actually downloaded. Kafka should now have an extracted directory such as `~/kafka_2.13-4.0.0`.

## Step 4: Understand Kafka's `bin` Directory

The extracted Kafka directory includes a `bin` folder containing command-line utilities, such as:

- `kafka-topics.sh` — manage Kafka topics.
- `kafka-console-producer.sh` — produce messages.
- `kafka-console-consumer.sh` — consume messages.
- `kafka-server-start.sh` — start a Kafka server when using a manual setup.

Without changing `PATH`, you can run a utility using its full or relative path:

```bash
~/kafka_2.13-4.0.0/bin/kafka-topics.sh --help
```

## Step 5: Add Kafka to PATH

The `PATH` environment variable tells your shell which directories to search for executable commands.

Open the Bash startup configuration:

```bash
nano ~/.bashrc
```

Add this line at the end, changing the directory name to match your installed version:

```bash
export PATH="$PATH:$HOME/kafka_2.13-4.0.0/bin"
```

Save in Nano using **Ctrl+X**, **Y**, and **Enter**.

Apply the change to the current terminal:

```bash
source ~/.bashrc
```

New Ubuntu Bash terminal sessions should also load this configuration automatically.

## Step 6: Verify Kafka CLI Access

From any directory, run:

```bash
kafka-topics.sh --help
```

If the help output appears rather than `command not found`, the PATH setup is working.

You can also inspect the resolved executable:

```bash
command -v kafka-topics.sh
```

## Step 7: Connect to a Running Kafka Broker

If Kafka is already running through Docker Compose and exposes port 9092 to your environment, you can try:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

This checks broker connectivity as well as CLI availability. If your Docker/WSL networking configuration differs, use the broker address configured for your environment.

## Common Troubleshooting

| Problem | Suggested check |
|---|---|
| `java: command not found` | Confirm Corretto was installed successfully inside Ubuntu. |
| Wrong Java version | Run `sudo update-alternatives --config java` and select Java 21. |
| `kafka-topics.sh: command not found` | Check the Kafka directory name, the `export PATH=...` line, and run `source ~/.bashrc`. |
| Kafka download cannot be extracted | Confirm you downloaded a binary `.tgz` archive and used its actual filename. |
| CLI works but cannot connect to Kafka | Confirm the broker is running and its advertised address and port are reachable from WSL2. |

## Key Takeaways

1. WSL2 provides the Ubuntu environment used for Kafka command-line development on Windows.
2. Amazon Corretto 21 supplies the Java runtime needed for the lecture's Kafka setup.
3. Kafka binaries contain useful `.sh` CLI utilities.
4. Adding Kafka's `bin` directory to `~/.bashrc` makes those commands available from anywhere in the Ubuntu terminal.
5. Installing Kafka CLI tools does **not** automatically start a Kafka broker.
6. If Docker Compose and Conduktor already run the broker, the CLI can interact with that existing Kafka installation.
7. The next lecture covers starting Kafka directly within WSL2 without Docker.

## Key concepts
1. Install Java JDK 21: Use Amazon Corretto on Ubuntu within WSL2.
2. Download Apache Kafka: Obtain Kafka 4.0 or later from the official Apache Kafka website.
3. Extract Kafka: Use wget to download and tar to extract the binaries.
4. Configure PATH: Add Kafka's bin directory to ~/.bashrc.
5. Verify Kafka CLI: Run kafka-topics.sh --help from any directory.
6. Docker integration: Use the installed CLI tools with Kafka running through Docker Compose and Conduktor.

## Important commands
|Command	             | Purpose                    |
|------------------------|----------------------------|
| java --version	     |Verify Java 21              |
| wget <URL>	         | Download Kafka             |
| tar -xvzf <archive>	 | Extract Kafka              |
| pwd	                 | Display current directory  |
| nano ~/.bashrc	     | Edit PATH configuration    |
| source ~/.bashrc       | Reload configuration       |
| kafka-topics.sh --help | Verify Kafka CLI           |

Example PATH configuration
Add the following to ~/.bashrc, adjusting the Kafka directory to match your installation:
```bash
export PATH="$PATH:$HOME/kafka_2.13-4.0.0/bin"
```

Reload the configuration:
```bash
source ~/.bashrc
```

Verify Kafka:
```bash
kafka-topics.sh --help
```

Key takeaway: After configuring PATH, Kafka CLI commands can be executed from anywhere in your Ubuntu WSL2 terminal without typing the full Kafka installation path.
