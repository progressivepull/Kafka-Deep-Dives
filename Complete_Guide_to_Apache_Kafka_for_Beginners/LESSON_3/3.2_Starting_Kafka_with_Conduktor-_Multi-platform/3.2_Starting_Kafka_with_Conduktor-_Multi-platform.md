# 3.2 Starting Kafka with Conduktor- Multi-platform

## Overview

This lecture demonstrates the instructor's recommended way to run **Apache Kafka** locally using **Docker Desktop** and the **Conduktor Console**. The approach works on Windows, macOS, and Linux and provides a graphical interface for learning and development.

> **Important:** After starting Kafka with Docker, follow the operating-system-specific lecture to install the **Kafka CLI binaries** separately.

## 1. Install Docker Desktop

1. Visit the [Docker Desktop installation page](https://www.docker.com/products/docker-desktop/).
2. Choose the version for your operating system:
   - **macOS:** Apple Silicon or Intel, as appropriate.
   - **Windows:** Install Docker Desktop with the **WSL2 backend** (strongly recommended by the instructor).
   - **Linux:** Follow the distribution-specific instructions.
3. Launch Docker Desktop and verify that it is running.

### Windows note

Use **WSL2 rather than Hyper-V** for the course setup. The instructor recommends WSL2 for compatibility with Kafka and later exercises.

## 2. Configure Docker resources

The instructor recommends these minimum allocations for the course environment:

| Resource | Recommended allocation |
| --- | --- |
| Memory | At least **8 GB** |
| CPU | At least **2 vCPUs** |

Adjust the resource limits in Docker Desktop settings where available. More resources can help if your computer supports them.

## 3. Get the Kafka Docker Compose project

Open the Conduktor repository:

**https://github.com/conduktor/kafka-stack-docker-compose**

Download the repository as a ZIP file or clone it:

```bash
git clone https://github.com/conduktor/kafka-stack-docker-compose.git
cd kafka-stack-docker-compose
```

The instructor points to the **single Kafka KRaft + Conduktor** setup, using a Compose file named around `conduktor-kafka-single`. The configuration starts services including:

- **Apache Kafka** — the local broker.
- **Conduktor Console** — a graphical Kafka management interface.
- **PostgreSQL** — a supporting database for the console.

The services are preconfigured in the project.

## 4. Start the stack

In the repository README, find the section **Single Kafka KRaft mode + Conduktor** and run its documented `docker compose` command from the appropriate directory.

> The transcript does not provide the exact Compose command or filename extension. Copy the current command from the repository README rather than guessing a command that might not match your downloaded version.

The first run downloads container images and may take several minutes. Wait for the Kafka and Conduktor services to initialize and become healthy.

## 5. Open Conduktor Console

Open the local web interface:

**http://localhost:8080**

Sign in using the credentials configured for your local Compose deployment. Confirm that the cluster (shown in the lecture as **My Local Kafka Cluster**) is available and healthy.

Conduktor lets you inspect clusters and topics and use Kafka without relying exclusively on terminal commands.

## 6. Verify Kafka by creating a topic

1. In Conduktor, open **Topics**.
2. Create a topic called **`demo_topic`**.
3. Return to the topic list and confirm that `demo_topic` appears.
4. Optionally delete the demonstration topic to leave the environment clean.

Successfully creating and viewing the topic is a simple sanity check that Kafka is running and accessible through Conduktor.

## 7. Install Kafka CLI tools separately

Even when Kafka is running in Docker, install the Kafka binaries for your operating system as described in the next relevant course lecture. The CLI tools allow you to interact with Kafka from a terminal.

## Key concepts

| Concept | Explanation |
| --- | --- |
| Docker Desktop | Runs the local containerized Kafka environment. |
| Docker Compose | Starts multiple configured services together. |
| Kafka broker | The server that stores and serves Kafka messages. |
| KRaft | Kafka's metadata management mode that does not require ZooKeeper. |
| Conduktor Console | UI for inspecting and managing Kafka resources. |
| PostgreSQL | Supporting database included in this Compose stack. |
| Kafka CLI | Command-line tools installed separately for course exercises. |
| WSL2 | Recommended Windows backend for Docker Desktop and Kafka coursework. |

## Troubleshooting tips

- Ensure Docker Desktop is running before executing the Compose command.
- On Windows, verify that Docker Desktop uses the WSL2 backend.
- Allow time for the initial image downloads and service startup.
- If the console is not immediately healthy, wait and review the Compose logs.
- Check that port **8080** is available if the local console does not open.
- Conduktor's UI may look different from older course recordings, but the same core functions should be available.

## Summary

**Recommended workflow:** Install Docker Desktop → configure resources → download the Conduktor Kafka Compose repository → run the README's single-Kafka KRaft setup → open `localhost:8080` → create `demo_topic` to test Kafka → install Kafka CLI tools for later lectures.

The main benefit is a simple, repeatable **local Kafka development environment with a UI**, avoiding the complexity of configuring a full Kafka cluster manually.


## Key takeaways
1. Install Docker Desktop — Use the WSL2 backend on Windows for better Kafka compatibility.
2. Configure Docker resources — The instructor recommends at least 8 GB RAM and 2 vCPUs.
3. Download the Kafka Docker Compose project — Use the conduktor/kafka-stack-docker-compose GitHub repository.
4. Start Kafka and Conduktor — Run the Docker Compose command provided in the repository's README.
5. Access Conduktor — Open http://localhost:8080 to manage Kafka through its graphical interface.
6. Verify Kafka — Create a topic named demo_topic and confirm that it appears in Conduktor.
7. Install Kafka CLI tools separately — Follow the operating-system-specific lecture to use Kafka terminal commands.
Important: The Docker setup uses Kafka in KRaft mode, which does not require ZooKeeper. Conduktor provides the UI, while Kafka CLI tools let you manage Kafka from the command line.
